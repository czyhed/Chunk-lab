# 上传、解析与入库

默认使用 Structure-Aware 自动切分。上传后点击「开始解析」，解析完成后使用「向量化并入库」，选择 Embedding 模型和数据库即可。该操作采用当前预览（没有预览时先生成），然后完成向量化和数据库写入。逐块完成标记、Context 增强及 SPU 商品归属是可选工作，不再阻止普通文档入库或导出。

人工修订仍可使用。替换已有修订的预览时保留确认提示；租约、内容版本、向量维度、模型失败等检查仍然生效。同一标签页刷新或丢失租约响应可恢复租约，其他标签页不能抢占正在编辑的文档。

## 父子分块

切块策略选择「父子分块」。父块按标题、商品身份和受保护内容边界组织，父块之间不重叠；文本子块在各父块内按 Token 切分，可配置重叠，不跨越父块边界。表格、图片和警告保留受保护的内容单元，可能超过子块预算。

| 参数 | 默认 | 规则 |
| --- | --- | --- |
| 父块 Token | 1536 | 整数，大于子块大小，最多 8192 |
| 子块 Token | 页面 384、API 512 | 32–4096 的整数 |
| 子块重叠 Token | 64 | 非负整数，小于子块大小；0 表示不重叠 |

`POST /api/batches/:batchId/documents/:documentId/chunks` 示例：

```json
{"strategy":"parent-child","parentChunkSize":1536,"chunkSize":384,"chunkOverlap":64,"imagePolicy":"summary"}
```

每个可检索子块保留 `parentChunk: {id, text, sourceSegments, childCount}`。子块与父块均保留原文定位。预览和详情可展开父块，JSON 导出也保留父子关系。向量仅基于子块正文及已确认的 Context 生成；父块上下文放在数据库记录的 `contentPayload.parentChunk` 中，无需新增数据库列。

修订或排除子块后，父块上下文从当前有效子块重新计算，去除相邻子块的精确重叠，避免返回已排除或旧的内容。只有同一父块内的子块可以合并。更改策略或尺寸后重新入库，新记录写入成功才清理旧切分记录；失败会显示重试入口。旧向量不能用于已变化的切分结果。

「分块检索测试」展示已入库的子块命中与父块全文。原「检索验证」仍打开 Agentic Retrieval 工作台；该服务也读取父块上下文用于检索结果与回答，并保留命中的子块 ID 和文本用于追踪。同一父块可由多个子块命中。

## 验证

`npm test`、`npm run typecheck`、`npm run build`。其中 `src/simple-workflow-http.test.ts` 覆盖上传、租约恢复、父子切分、无需 SPU 的入库、父块检索、导出、旧记录清理及过期向量拒绝；`src/parent-child.test.ts` 覆盖分块尺寸、原文区间、父块持久化及修订/排除。
