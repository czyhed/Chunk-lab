Chunk Lab：从原始资料到可检索知识

面试现场展示版｜主线：复杂资料 → 人工审核 → 可靠下游产物

STAR 总览

S · Situation

资料复杂且不可直接入库

PDF、Office、图片、表格和公式混杂，直接切块会丢失结构与来源。

T · Task

建立可靠生产链路

让每个 Chunk 可审核、可追溯，并能安全进入检索与导出。

A · Action

解析、核对、修订、门禁

MinerU 解析后，使用 Preview/Draft 隔离和人工审核控制下游资格。

R · Result

结果可验证

Embedding、pgvector、Recall@K、导出和刷新恢复均有可观察结果。

flowchart LR S[复杂资料] --> P[解析与标准化] P --> V[Preview 预览] V --> D[Draft 人工修订] D --> G[资格门禁] G --> E[Embedding] G --> M[Markdown 导出] E --> R[向量检索验证]

现场操作流程

  1. 上传一份代表性 PDF，展示批次创建与解析状态。
  2. 打开 Parsed Document，展示原文、解析块和来源定位。
  3. 调整切分策略，明确点击“应用参数并生成预览”。
  4. 在 Preview 中看质量指标（分块数、平均 Token、过短/超长），并点 Chunk 与原文互相定位高亮。
  5. 点“采用此 Preview”把预览确认为可编辑的 Draft，再演示修改、拆分、合并或排除。
  6. 只选择合格 Chunk 执行 Embedding，再运行检索验证。
现场讲法：“我把模型调用放在人工审核之后，先证明内容和来源正确，再让它进入向量库。”

展示边界：说明“本地 Docker 验收完成、线上生产部署未宣称”；真实数据、fake supplier 和历史计划要按证据区分。

可引用结果

真实 PDF 验收：23 页、257 个 source blocks、55 个 Draft Chunks；Embedding 38 个成功、17 个跳过；Recall@5 对人工确认相关 Chunk 命中 1/1；刷新与重启恢复通过。

建议现场只强调：可追溯、可控、可验证。不要把系统描述成多用户 SaaS、正式线上知识库或全量自动化 VLM 流程。
