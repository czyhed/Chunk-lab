# Chunk Lab 电商文档审阅台使用手册

> 适用版本：截至 2026-08-17 的当前实现  
> 适用对象：使用桌面网页端完成文档解析、切分和数据标注的审核人员  
> 不在本文范围：移动端、服务部署、账号与权限、密钥配置、对象存储和数据库运维、HTTP API

## 1. 手册用途

Chunk Lab 用于把 PDF、Office、图片或文本文件转换为可追溯的 Chunk Draft，并由人工完成来源核对、内容修订、图片摘要、Context 审核、Embedding、数据库写入和导出 

本手册既可作为首次培训教程，也可在日常操作中按章节查阅。界面中的模型和数据库选项由服务端提供，本文不固定列出供应商或具体模型名称。

### 1.1 核心原则

1. **原文是不可变参考。** 人工修改发生在 Chunk Draft 或人工标注层，不会改写 Source Document 和 Parsed Document。
2. **Preview 与 Draft 分离。** 调整参数只形成配置草稿；生成 Preview 后仍需人工确认，才会形成可修订的 Draft。
3. **每份文档独立处理。** 同一 Parse Batch 中，一份文档失败不会阻止其他文档进入审阅。
4. **来源必须可追溯。** 每个 Chunk 应能回到对应页码、来源框或 Source Segment。
5. **模型结果必须审核。** 图片 VLM 摘要和 Context 都不会因为生成成功就自动成为最终人工结论。
6. **先保存，再进入下游。** 修改 Chunk、图片摘要或 Context 后，应等待页面显示保存完成，再执行 Embedding、数据库写入或导出。

## 2. 开始前准备

### 2.1 浏览器和访问地址

- 使用桌面浏览器打开管理员提供的 Chunk Lab 地址。
- 局域网多人访问应优先使用管理员提供的 HTTPS 地址。`http://localhost`通常属于浏览器安全上下文，但普通 `http://<局域网 IP>:4180` 不一定具备相同能力，不应通过浏览器“标记为可信来源”代替 HTTPS。
- 推荐在稳定网络下操作，不要同时在多个标签页编辑同一文档。
- 页面 URL 中带有 `batchId` 时，请保留完整 URL；它可用于刷新或重新打开同一批次。
- 同一浏览器也会记住最近打开的批次，但完整批次 URL 是更可靠的恢复入口。

### 2.2 支持的文件格式

| 文件类型 | 扩展名 | 使用提示 |
| --- | --- | --- |
| PDF | `.pdf` | 最适合保留原始页面、页码和 bbox 定位。扫描版建议启用 OCR。 |
| Word | `.docx` | 解析后可通过 Visual Copy 对照版面；复杂浮动对象需重点复核。 |
| PowerPoint | `.pptx` | 按幻灯片页审阅；重点检查文本框、图片、图注和阅读顺序。 |
| Excel | `.xlsx` | 重点检查表头、合并单元格、跨页或跨行组表格。 |
| 图片 | `.png`、`.jpg`、`.jpeg` | 作为单页原始图片处理；可形成图片 Chunk 并进行 VLM 摘要。 |
| Markdown | `.md` | 直接解析文本结构，不需要 OCR。 |
| 纯文本 | `.txt` | 直接解析文本；原文件缺少版面信息时，来源定位可能只有文本范围。 |

不支持的扩展名不会进入有效解析。不要仅通过修改文件扩展名来伪装格式。

### 2.3 数据和费用检查

在上传前确认：

- 文件已获得处理授权，不含不应进入该环境的敏感数据。
- 文件不是损坏包、加密 Office 文档或带密码 PDF。
- 扫描件是否需要 OCR；公式和表格是否需要识别。
- 管理员已配置所需的解析、VLM、Context、Embedding 和数据库服务。

以下按钮可能触发外部模型或解析服务并产生费用：`开始解析`、`发送图片并生成摘要`、`生成 Context`、`开始向量化`。不要因页面暂时未更新而连续重复点击。

## 3. 界面总览

![桌面网页端总览](../output/evidence/storage-production-like-closure-v2/browser-desktop-1440x1000.png)

桌面界面分为四个主要区域：

| 区域 | 位置 | 作用 |
| --- | --- | --- |
| 顶栏 | 页面顶部 | 查看保存状态、选择导出契约、导出 JSON、下载 Manifest。 |
| 工作文件 | 左侧 | 添加文件、设置解析参数、开始解析、切换文档、重试或下载诊断包。 |
| 原文区 | 中间 | 查看原始文件或解析结果、翻页缩放、核对来源框、进行人工标注。 |
| Chunk 审阅区 | 右侧 | 设置切分策略、查看质量指标、确认 Preview、修订 Draft、处理模型和数据库任务。 |

可以拖动原文区和 Chunk 区之间的分隔条调整宽度；双击分隔条恢复默认宽度。点击左上角菜单按钮可收起或展开文件栏。

## 4. 首次完整演练

第一次使用时，建议只选一份结构清晰、页数较少且同时包含文字和图片的文件。

1. 点击 `添加文档`，选择文件；也可以把文件拖到上传区。
2. 展开 `解析设置`，确认模型、语言、OCR、表格和公式选项。
3. 点击 `开始解析`，等待文件状态从 `上传中`、`排队`或`解析中`变为`已就绪`。
4. 在原文区翻页，检查页面数量、文本框、图片框、表格框和阅读顺序。
5. 在 `切分配置` 中选择策略与图片策略。
6. 自动策略点击 `应用参数并生成预览`；人工策略先修订来源框，再点击 `生成当前页`或`生成整文档 Chunk`。
7. 查看 `质量指标`，逐个点击 Chunk，对照原文和 `Source Segments`。
8. 满意后点击 `采用此 Preview`，进入 `Draft`。
9. 在 Draft 中完成文本、类型、表格、图片策略、文字关联、图片摘要和 Context 审核。
10. 需要向量和数据库时，依次执行 `选择 Embedding 模型`和`选择数据库`。
11. 选择契约 `2.1`，点击 `导出 JSON`；需要清单时再点击 `下载 Manifest`。
12. 刷新页面，确认批次、Draft 和已保存审核状态能恢复。

## 5. 添加文档与开始解析

### 5.1 建立 Parse Batch

一次选择的多份文件会组成一个 Parse Batch。系统会去除同名且同大小的重复待上传项，但不会替你判断内容是否为另一个版本。

添加文件后：

1. 检查左侧文件数量和名称。
2. 展开 `解析设置`。
3. 选择解析模型：
   - `VLM 高质量`：适合复杂版面、图文混排和质量优先场景。
   - `Pipeline`：适合管理员确认可用的常规解析链路。
4. 选择语言：`中英混合`或`英文`。
5. 按文件特点设置：
   - `OCR`：扫描 PDF 或图片文字无法直接提取时启用。
   - `表格`：需要保留表格结构时启用，默认开启。
   - `公式`：包含数学或技术公式时启用，默认开启。
6. 点击 `开始解析`。

解析设置应用于本次提交。需要使用另一套设置时，应另建批次或在确认影响后重新解析单份文档。

### 5.2 文件状态

| 状态 | 含义 | 应对方式 |
| --- | --- | --- |
| `待解析` | 文件只在浏览器待提交列表中 | 完成解析设置后点击 `开始解析`。 |
| `上传中` | 正在把原文件提交给服务端 | 保持页面打开，不要重复点击。 |
| `排队` | 服务端已接收，等待解析 | 正常等待。其他文档可独立推进。 |
| `解析中 x/y` | 正在处理，已提取 x 页，共 y 页 | 正常等待；大文件可能需要较长时间。 |
| `已就绪` | Parsed Document 可用于预览和审阅 | 点击文件进入审阅。 |
| `失败` | 当前文档未完成解析 | 查看错误说明，下载诊断包，确认原因后再点`重试`。 |
| `Visual Copy失败` | Office 对照版转换失败 | 解析内容可能仍可用；重点检查来源定位，并下载诊断包交给管理员。 |

`载入演示`只用于熟悉界面，不应作为真实数据验收或正式交付结果。

### 5.3 重新解析

`重新解析`可能再次调用外部解析服务。点击后页面会要求确认。

当文档已有 Preview 或 Draft 时，重新解析会清除该文档旧的 Parsed Document、Preview、Draft、Revision 和 Context。操作前应：

1. 导出需要保留的结果。
2. 记录当前切分策略和关键参数。
3. 确认确实需要替换 Parsed Document，而不是只调整 Chunk。
4. 确认后只点击一次，并等待状态更新。

解析失败后的`重试`与已完成文档的`重新解析`都只作用于当前文档，不会重跑整个批次。

## 6. 查看原文和来源定位

### 6.1 页面和视图

原文区可使用：

- 页码标签或`页码`输入框跳转。
- `上一页`、`下一页`切换页面。
- `缩小`、`适宽`、`实际大小`、`放大`调整阅读比例。
- `原始文件`和`解析结果`标签切换可用视图。

PDF 与 Office Visual Copy 通常保留页面定位；图片只有一页；Markdown/TXT 的来源视图可能没有与 PDF 相同的版面层。

### 6.2 原文与 Chunk 双向定位

- 点击 Chunk，原文区会跳到其首个来源位置并高亮相关来源框。
- 点击来源框或详情中的 `Source Segments`，Chunk 列表会定位到相关 Chunk。
- `Ctrl` 加点击可累加来源选择。
- `OVERLAP` 表示该来源片段被相邻 Chunk 重叠引用，不代表重复错误。
- 点击原文区右上角的`清除来源锁定`，或按 `Esc`，可清除当前关联选择。

若提示“所选来源暂无对应 Chunk”，说明当前 Preview/Draft 没有引用该来源。应检查它是否被排除、是否只存在于人工层，或是否需要重新生成 Preview。

## 7. 选择切分策略

### 7.1 策略选择表

`切分配置`默认可以折叠成一行摘要；需要调整策略或参数时点击摘要展开。

![切分配置展开状态](../output/evidence/review-layout-vlm-context-workflows/layout-1440x1100-draft-expanded.png)

| 策略 | 适用场景 | 主要参数 | 注意事项 |
| --- | --- | --- | --- |
| `人工框选切分` | 版面复杂、自动检测错误明显、需要逐页精确控制 | 无统一 Token 参数 | 先修订来源框，再按页或整文档生成。工作量最大，控制最精确。 |
| `Structure-Aware` | 标题层次清晰、产品章节、图片/表格与说明需要保持组合 | `最大 Token`、`Overlap` | 优先保护结构和内容组，适合作为大多数产品文档的首选。 |
| `SentenceSplitter` | 连续自然语言说明、段落型文档 | `最大 Token`、`Overlap` | 优先保持完整句子，可能产生较短块。 |
| `TokenTextSplitter` | 需要稳定 Token 尺寸、结构要求较弱 | `最大 Token`、`Overlap` | 尺寸最直接，但可能在语义或结构边界附近切开。 |
| `Semantic Boundary` | 主题切换明显、需要语义断点辅助 | `Buffer`、`断点 %`、`最大 Token` | 需要可用的 Embedding 服务；阈值越高通常断点越少。 |

### 7.2 参数规则

- `最大 Token`控制文本 Chunk 的目标上限。
- `Overlap`用于保留相邻 Chunk 的上下文，必须小于 Chunk 大小。
- `Buffer`控制 Semantic Boundary 比较断点时使用的相邻句窗口。
- `断点 %`控制语义距离达到什么百分位时建议断开。

调整策略或参数后，配置会标记为未应用。系统不会自动生成新结果；必须点击`应用参数并生成预览`。

### 7.3 图片策略

| 策略 | 结果 |
| --- | --- |
| `摘要 + 引用` | 保留图片对象引用；人工确认后的图片摘要默认作为图片 `finalText`，可选关联多个同文档文字 Chunk。关联文字不会自动拼入图片摘要。 |
| `仅引用` | 不生成 VLM 摘要，必须关联至少一个同文档内有效、可检索的文字 Chunk。图片自身没有文本 `finalText`、Context 或文本 Embedding，下游通过关联文字 Chunk 工作。 |
| `排除` | 图片不进入有效下游检索，不要求摘要或文字关联。 |

配置区的图片策略是生成 Preview 时的默认策略。进入 Draft 后，可以在单个图片 Chunk 中调整其图片策略。

## 8. 人工框选切分

人工框选模式使用 MinerU 检测框作为起点，在独立人工标注层中修订，不改写解析结果。

### 8.1 常用工具

| 工具 | 操作 |
| --- | --- |
| `选择` | 点击来源框；按住 `Ctrl` 可多选。 |
| `新建文本框` | 在页面上拖出新框，再选择类型。 |
| `类型` | 设置为文本、标题、表格、图片、列表、公式、代码、警告或图注。 |
| `合并同页` | 把同一页的多个选中框合并为一个来源框。 |
| `跨页选择` | 开启跨页收集，再去其他页面选择来源框。 |
| `合并跨页` | 把选中的跨页来源框组成一个逻辑组。 |
| `拆分` | 恢复此前合并的成员。 |
| `排除` | 切换选中来源框的排除状态，可恢复。 |
| `删除框` | 删除人工框；这不是删除原文件或 Parsed Document。 |
| `撤销`、`重做` | 撤销或恢复人工标注层的操作。 |

人工文字框没有可用文字时，在详情区填写`人工转录文字`。文字保存在人工修订中，页码和框坐标仍作为来源，不会写回 Parsed Document。

### 8.2 生成 Chunk

- `生成当前页`：只根据当前页有效来源框形成部分 Preview，适合逐页检查。
- `生成整文档 Chunk`：根据所有页面的人工标注形成完整 Preview。
- `创建 Chunk`：使用当前来源选择新建 Chunk。
- `加入当前 Chunk`：把选中来源加入当前 Chunk。
- `移出当前 Chunk`：从当前 Chunk 移除选中来源。

生成当前页后看到“部分 Preview”是正常状态。正式确认前，应完成所有相关页面并生成整文档结果。

## 9. 审核 Preview

Preview 是可重新生成的提案，不是最终 Draft。

### 9.1 质量指标

完成一次 Preview 或 Draft 后，配置区可以收起，把纵向空间留给质量指标和 Chunk 列表。

![切分配置折叠后的 Draft 审阅区](../output/evidence/review-layout-vlm-context-workflows/layout-1440x1100-draft-collapsed.png)

展开`质量指标`可查看：

- Chunk 数量和平均 Token。
- Token 分布、跨页情况和实际重叠比例。
- 过短、超长、图片块、表格块和 Quality Flag 数量。
- 与现有 Draft 的变化提示（已有 Draft 时）。

质量指标是审核线索，不是自动合格分数。应结合业务语义、原文结构和下游检索需求判断。

### 9.2 逐块检查

对每个 Chunk 至少确认：

1. 内容是否完整、无明显漏字或乱码。
2. 类型是否正确，例如标题、文本、图片、表格。
3. Source Segments 是否指向正确页码和区域。
4. 表格、图片和图注是否保持合理关系。
5. `过短`、`超长`、`OVERLAP`和其他 Flag 是否可接受。
6. 同一产品、型号或适用范围是否被错误混合。

### 9.3 确认或放弃

- 点击`采用此 Preview`后，Preview 成为 Chunk Draft，并进入可编辑状态。
- 如果调整参数后按钮显示`请先生成新 Preview`，必须重新生成，不能采用旧结果。
- 已有 Draft 时，可以点击`放弃 Preview`返回当前 Draft。
- 用新 Preview 替换已有 Draft 可能清除人工修订和 Context。页面会显示受影响数量；不确认就不会替换。

## 10. 修订 Draft

只有 Draft 中可以进行人工修订、Context、Embedding 和数据库写入。

### 10.1 文本和类型

1. 选择 Chunk。
2. 点击`编辑`。
3. 在`审阅类型`中选择正确类型，或修改正文。
4. 离开编辑框时，系统会保存并由服务端重新计算派生状态。
5. 等待顶栏状态显示`已保存并重算`后再继续。

`恢复自动文本`会丢弃该 Chunk 的人工正文修改并恢复自动结果。`自动结果差异`用于对照，不是另一个编辑框。

### 10.2 拆分、合并、排除和恢复

- `在光标拆分`：把光标放到文字 Chunk 的目标位置后点击。人工改写导致无法精确推导来源时，应先恢复自动文本再拆分。
- `合并下一块`：只允许合并相邻且类型兼容的 Chunk。
- `排除`：Chunk 保留在 Draft 和审计轨迹中，但不进入有效 Embedding 下游；可点击`恢复`撤销。
- `撤销`、`重做`：作用于当前 Draft 修订历史。

“排除 Chunk”与“删除人工来源框”都不是删除整份文档。

### 10.3 表格修订

将审阅类型设为`table`后，可编辑：

- 表格标题、列标题和单元格文字。
- `+ 行`、`+ 列`和`- 列`。
- `合并选中`和`拆分单元格`。
- 删除指定行。

合并单元格必须选择连续的完整矩形，且不能跨来源行组。包含跨行单元格时，部分增删操作会被阻止；先拆分相关单元格再继续。点击`保存表格`后等待服务端重算完成。

## 11. 图片策略、文字关联与 VLM

![图片摘要和 Context 审核](../output/evidence/review-layout-vlm-context-workflows/workflow-1440x1100-context-confirmed.png)

### 11.1 先决定图片策略

选择图片 Chunk 并点击`编辑`后，先判断下游需要：

- 图片本身需要可检索语义时，选择`摘要 + 引用`，人工确认摘要；是否追加文字关联由审核人员决定。
- 图片只应借助正文、图注或说明文字参与检索时，选择`仅引用`，并至少选择一个有效文字 Chunk。
- 图片不应参与检索时，选择`排除`。

`仅引用`会隐藏或禁用图片理解模型和发送摘要按钮，不会发起 VLM 请求。没有有效文字关联时，页面会阻止保存并显示“原因、影响、下一步”。

### 11.2 添加或移除关联文字 Chunk

1. 在图片 Chunk 详情中找到`关联文字 Chunk`。
2. 使用搜索框按 Chunk ID 或正文搜索当前文档中的候选项。
3. 勾选一个或多个文字 Chunk；再次取消勾选即可移除。
4. 检查已选数量和候选正文，避免只凭相近 ID 建立关系。
5. 点击`保存图片策略`，等待保存完成。

关联对象必须属于同一文档，且必须是未排除、未失效并具备检索资格的文字 Chunk。图片不能关联自身，也不能关联图片、表格或不存在的 Chunk。重复选择会由系统去重。

文字 Chunk 被排除、删除、替换或失去检索资格后，服务端会重新校验图片关系。详情中出现失效关联提示时，恢复原文字 Chunk，或选择新的有效文字 Chunk 并重新保存。系统不会把失效对象悄悄保留为有效下游关系。

### 11.3 何时处理图片摘要

下面是一次图片摘要保存后的桌面状态示例：右侧同时保留可信来源、原始摘要、人工摘要、人工补充和最终生效文本。

![图片摘要已保存](../output/evidence/review-layout-vlm-context-workflows/workflow-1440x1100-image-saved.png)

图片 Chunk 显示`建议增强 · 待补充图片摘要`时，说明其检索文本尚不完整。点击`填写图片摘要`或选择该 Chunk 后点击`编辑`。

### 11.4 “摘要 + 引用”操作步骤

1. 确认`可信来源图片`存在；没有可信原图或精确 PDF 裁剪时，不应发送模型。
2. 将单 Chunk 的`图片策略`设为`摘要 + 引用`；按需添加文字关联。
3. 从`图片理解模型`下拉框选择管理员提供的 profile。
4. 点击`发送图片并生成摘要`。该操作可能产生模型费用，只点击一次并等待结果。
5. 阅读只读的`VLM 原始摘要`，对照原图检查商品、型号、数值、单位、颜色、适用范围和图中文字。
6. 在`人工摘要`中改写错误或不完整内容。
7. 在`人工补充`中增加对检索有帮助、且能从原文确认的信息。
8. 检查`最终生效文本`。
9. 点击`保存图片策略`，等待页面显示保存成功。

`最终生效文本`默认来自人工确认后的图片摘要。文字关联独立保存，不会自动拼接到图片 `finalText`；需要补充图片语义时，应在`人工摘要`或`人工补充`中明确写入并复核。

VLM 失败或超时不会覆盖已保存摘要。可根据页面的“原因、影响、下一步”处理，或改用人工摘要。不要把无法从图片或原文确认的推测写入人工补充。

真实 VLM 验收时，模型 provenance 会显示在摘要状态区域；审核时应以图片内容和人工复核为准，不把模型名称当成正确性证明。

## 12. Context Enhancement

Context 是附加在 Chunk 外的背景说明，只在下游 Embedding 时与正文组合，不替代 Chunk 原文。

### 12.1 推荐与资格

- `CONTEXT 推荐`表示规则认为该 Chunk 可能依赖文档外部信息，不表示必须生成。
- 未被推荐的合格 Chunk 仍可人工选择生成。
- 显示`不可生成`时，展开其原因、影响和下一步。常见原因包括被排除、内容未确认、图片摘要缺失或内容不完整。
- `摘要 + 引用`图片通常需要先保存有效图片摘要，才会解锁 Context。
- `仅引用`图片自身始终不进入 Context；需要 Context 时，应在其关联的合格文字 Chunk 上生成和审核。

### 12.2 批量生成

1. 在 Draft 的 Chunk 卡片上勾选`选择生成`。
2. 使用`生成已选 Context`；或点击`生成 P.x 推荐`处理当前页推荐项。
3. 选择 Context 模型。列表来自服务端，不需要也不允许在前端输入密钥。
4. 等待工具栏显示生成完成、待审核、失败和跳过数量。

若选中项中已有`已确认`或`人工修改`的 Context，页面会在覆盖前再次确认。除非确实需要重生成，否则取消覆盖。

### 12.3 单块审核

Context 状态含义：

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| `未生成` | 尚无 Context | 可选择模型生成，或直接填写人工 Context。 |
| `生成中` | 模型请求尚未结束 | 等待，不要重复提交。 |
| `待审核` | 模型结果已返回但未确认 | 对照正文和来源检查，然后确认或人工修改。 |
| `已确认` | 模型结果已人工确认 | 可进入 `embeddingText`。 |
| `人工修改` | 人工保存了 Context | 可进入 `embeddingText`。 |
| `失败` | 当前请求失败 | 已保存内容不受影响；诊断后可重新生成或人工填写。 |
| `已失效` | Chunk 内容、结构或来源在生成后变化 | 旧 Context 只供审阅，不进入 `embeddingText`；重新生成或保存新的人工 Context。 |

操作方式：

- `生成 Context`：只生成当前 Chunk。
- `保存人工 Context`：保存人工编写或修改后的 2-4 句背景说明。
- `确认 Context`：确认处于`待审核`的模型结果。
- `实际采用的 Context 范围`：查看模型使用了哪些文档范围。
- `跳过的邻居`：查看哪些相邻 Chunk 因规则被排除。

Context 应补充产品名称、型号、章节、适用范围等必要背景，不应重复整段正文，也不应加入来源中不存在的事实。

![Context 已确认的桌面状态](../output/evidence/review-layout-vlm-context-workflows/workflow-1440x1100-context-confirmed.png)

## 13. Embedding 与数据库写入

这两个入口只在 Draft 中显示。修改 Draft、图片摘要或 Context 后，应重新完成相应的 Embedding 和数据库写入，确保下游记录对应最新版本。

### 13.1 Embedding

1. 点击`选择 Embedding 模型`。
2. 从列表中选择模型；界面会显示维度和最大 Token。
3. 点击`开始向量化`。
4. 查看每个 Chunk 的`成功`、`失败`或`跳过`状态。
5. 若为部分失败，按钮会变为`重试失败项`，只在确认故障原因后重试。

被排除、不合格或没有有效最终文本的 Chunk 会跳过。`仅引用`图片自身会跳过文本 Embedding，其关联文字 Chunk 按各自资格正常处理。界面不会显示向量值。

### 13.2 数据库

1. 先确保所需 Embedding 任务已完成。
2. 点击`选择数据库`。
3. 选择管理员提供的目标数据库。
4. 点击`提交向量记录`。
5. 查看`已写入`、`未变化`、`已删除`、`失败`和`跳过`数量。
6. 部分失败时，只使用`重试失败项`处理失败项。

`未变化`表示数据库已存在相同版本，无需重复写入；`已删除`通常表示该 Chunk 在新版本中已被排除或删除。数据库 profile、连接信息和向量内容不会在网页中公开。

## 14. 导出与 Manifest

### 14.1 导出 JSON

只要批次中至少一份文档已有 Draft，顶栏`导出 JSON`即可使用。

1. 在`契约`中选择版本。
2. 新流程默认选择`2.1`；只有下游明确要求旧格式时才选择`Legacy`。
3. 点击`导出 JSON`。
4. 检查下载文件名、契约版本、文档清单和 Chunk 数量。

Contract 2.1 会保留来源、配置、人工修订、质量标记、图片 `relatedChunkIds` 和模型 provenance。只有`已确认`或`人工修改`且未失效的 Context 才会进入 `embeddingText`。图片关联不会自动拼入图片 `finalText`；`仅引用`图片导出时保持空文本和自身不参与文本下游的状态。

### 14.2 下载 Manifest

`下载 Manifest`只下载批次级清单和统计，不包含完整 Chunk 正文。它适合交付核对，不可替代完整 JSON 导出。

导出内容不应包含二进制、base64、data URL、Authorization、连接信息、API Key、预签名 URL 或向量值。发现这些内容时停止交付并联系管理员。

## 15. 诊断、失败隔离与重试

### 15.1 阅读错误框

页面错误按三个部分显示：

- `原因`：当前操作为什么没有完成。
- `影响`：哪些结果未生成，以及哪些已保存结果仍然安全。
- `下一步`：标注人员可以执行的恢复动作。

优先按`下一步`处理，不要反复点击原按钮。

### 15.2 下载诊断包

左侧文档出现解析失败、MinerU 结果异常、bbox/页码异常或 Visual Copy 失败时，会显示`下载诊断包`。

1. 点击一次并等待`已下载`。
2. 保留文件名和对应文档名称。
3. 把诊断包交给管理员，不要自行修改其中字段后再次导入。
4. 诊断包通常有有效期；过期后需从网页重新生成。

诊断包用于定位问题，不是正式导出，也不应包含密钥、鉴权头或密码。

### 15.3 常见问题处理

| 现象 | 可能原因 | 网页端处理 |
| --- | --- | --- |
| `开始解析`不可点击 | 尚未添加有效文件 | 重新选择受支持文件。 |
| 局域网地址添加文件后无反应 | 当前入口是非安全 HTTP，浏览器缺少页面所需的安全上下文能力；异常发生在入队前 | 优先改用管理员提供的 HTTPS 地址；临时可在服务器本机使用 `localhost`。若控制台出现 `crypto.randomUUID is not a function`，说明请求尚未发出，与对象存储或数据库无关。 |
| 上传后回到`待解析` | 上传请求失败或网络中断 | 检查网络；确认没有产生批次后再提交。 |
| 单份文件`失败` | 文件损坏、格式问题或解析服务失败 | 下载诊断包；确认原因后只重试该文档。 |
| `Visual Copy失败` | Office 转换失败 | 使用可用解析结果继续核对，或交管理员处理后重新解析。 |
| Preview 无法采用 | 参数已变更或 Preview 已过期 | 点击`应用参数并生成预览`生成新结果。 |
| 来源没有对应 Chunk | 来源被排除或当前结果未引用 | 检查人工层和配置，必要时重新生成 Preview。 |
| VLM 按钮不可用 | 没有可信图片、没有 profile 或不在编辑状态 | 进入 Draft 编辑图片 Chunk；仍不可用时联系管理员。 |
| `仅引用`图片无法保存 | 尚未关联有效文字 Chunk，或原关联已经失效 | 搜索并选择同文档内至少一个未排除、可检索的文字 Chunk，再保存图片策略。 |
| 图片关联出现失效提示 | 关联文字 Chunk 已排除、删除、替换或失去检索资格 | 恢复原文字 Chunk，或移除失效项并选择新的有效文字 Chunk。 |
| VLM/Context 失败 | 超时、服务不可用或返回无效结果 | 已保存内容不会被覆盖；使用人工结果或在诊断后重试。 |
| Context `已失效` | Chunk 内容或来源发生变化 | 重新生成，或保存新的人工 Context。 |
| Context 不可选择 | Chunk 被排除、内容不合格或图片摘要缺失 | 根据页面原因修订并保存，再重新选择。 |
| Embedding 部分失败 | 个别 Chunk 超长、服务错误或资格变化 | 检查失败项，修订后使用`重试失败项`。 |
| 数据库写入失败 | Embedding 未完成、目标不可用或版本冲突 | 先完成 Embedding；仍失败时保留结果并联系管理员。 |
| 表格保存冲突 | 同一 Chunk 已被其他页面修改 | 刷新并基于最新版本重新编辑。 |
| 刷新后没有恢复 | URL 缺少有效 batchId、批次已过期或服务不可用 | 使用完整批次 URL重试；无效时联系管理员。 |

同一错误连续出现两次且没有新信息时，应停止重复操作，下载诊断包或联系管理员。

## 16. 刷新、关闭和恢复

### 16.1 可以恢复的内容

通过同一 `batchId` 重新打开时，已保存的解析结果、Preview/Draft、人工修订、图片摘要、Context 状态、Embedding 任务和数据库任务应由服务端恢复。

### 16.2 可能丢失的内容

- 尚未离开编辑框、页面仍显示保存中的文字。
- 尚未点击`保存图片摘要`的人工摘要和补充。
- 尚未点击`保存人工 Context`或`确认 Context`的内容。
- 只存在于当前浏览器中的临时选择、滚动位置和未提交文件。

刷新或关闭前，检查顶栏保存状态，不要在`生成中`、`保存中`或`服务端重算中`时关闭页面。

界面底部的`临时工作区 24H`是工作区提示，不应被理解为所有业务对象的统一保留承诺。正式保留期限由管理员的存储和生命周期合同决定。

## 17. 删除与保留边界

当前桌面网页端没有“删除整份文档”按钮。标注人员在网页中可以执行的相关动作只有：

- `排除` Chunk：可恢复，影响下游资格，不删除原文。
- `删除框`：删除人工标注框，不删除 MinerU 原始检测或原文件。
- 删除表格行/列：只修改当前 Draft 的表格模型。
- `放弃 Preview`：丢弃未采用的 Preview，保留已有 Draft。
- `重新解析`：替换当前文档的解析与审阅链，必须先确认影响。

需要删除整份文档或其持久化对象时，联系管理员按正式删除流程处理。不要把“排除”当成数据删除证明。

## 18. 交付前检查清单

### 18.1 文档与来源

- [ ] 批次内每份目标文档都为`已就绪`，或已单独记录失败原因。
- [ ] 页数、原文视图和解析结果与源文件一致。
- [ ] 图片、表格、图注、公式和警告没有明显遗漏。
- [ ] 所有关键 Chunk 都能定位到正确 Source Segments。
- [ ] 没有把不同产品、型号或版本错误合并。

### 18.2 Preview 与 Draft

- [ ] 当前参数已经生成 Preview，不存在未应用的配置更改。
- [ ] 过短、超长、跨页和 OVERLAP 已逐项判断。
- [ ] Preview 已明确采用并形成 Draft。
- [ ] 人工文本、类型、拆分、合并、排除和表格修订均已保存。
- [ ] 顶栏不再显示保存中或重算中。

### 18.3 图片、Context 与下游

- [ ] 图片策略正确；`摘要 + 引用`有经过人工复核的摘要，`仅引用`至少关联一个有效文字 Chunk，`排除`不进入下游。
- [ ] 图片关联均来自同一文档的可检索文字 Chunk，没有失效项；关联文字没有被误当作图片摘要自动拼接。
- [ ] VLM 原始摘要中的数字、型号和商品信息已对照原图。
- [ ] Context 为`已确认`或`人工修改`，没有未处理的`待审核`或`已失效`。
- [ ] 不合格或排除的 Chunk 已确认不会进入 Embedding。
- [ ] 最新 Draft 已完成所需 Embedding 和数据库写入，部分失败已记录。

### 18.4 导出与恢复

- [ ] 导出契约与下游要求一致，默认使用 Contract 2.1。
- [ ] JSON 和 Manifest 的批次、文档和 Chunk 数量正确。
- [ ] 导出中没有凭证、连接信息、预签名 URL、二进制或向量值。
- [ ] 使用完整批次 URL刷新后，已保存状态可以恢复。
- [ ] 失败文档的诊断包和处理结论已单独保存。

## 19. 术语表

| 术语 | 含义 |
| --- | --- |
| Parse Batch | 一次由审核人员开始解析的一组 Source Document。 |
| Source Document | 上传的原始文件，是不可变参考。 |
| Parsed Document | 从原文件解析出的结构化文档，保留内容、结构和来源位置。 |
| Content Block | Parsed Document 中有顺序和来源位置的内容单元。 |
| Chunk Preview | 应用配置后生成、尚未确认的切分提案。 |
| Chunk Draft | 已确认并可人工修订的 Chunk 集合。 |
| Source Segment | Chunk 精确引用的 Content Block 局部或整体。 |
| Quality Flag | 提醒人工关注解析或切分风险的标记，不等于自动判定失败。 |
| Model Enrichment | VLM 摘要或 Context 等模型生成内容，并保留模型和 prompt provenance。 |
| Context Enhancement | 与 Chunk 正文分开保存、只在下游 Embedding 时组合的背景说明。 |
| `relatedChunkIds` | 图片 Chunk 独立保存的同文档文字 Chunk 关联 ID；用于关系和下游路由，不自动改写图片 `finalText`。 |
| `embeddingText` | 用于 Embedding 的文本；可包含有效 Chunk 正文和已确认/人工修改的 Context。 |
| Export Package | 包含 Draft、来源、配置、修订和质量信息的批次导出快照。 |

## 20. 何时联系管理员

出现下列情况时停止重复操作并联系管理员：

- 模型或数据库下拉框显示`服务未配置`。
- 同一付费操作连续失败，且网页没有提供新的原因。
- 原始文件不可用，导致无法重新解析或生成可信图片。
- 批次 URL无法恢复已保存结果。
- 诊断包无法生成或已过期。
- 数据库写入持续失败、维度不匹配或记录状态异常。
- 发现网页、导出或诊断包中包含密钥、Authorization、密码、连接串、预签名 URL或向量值。
- 需要删除整份文档、恢复已删除数据或确认正式保留期限。

向管理员提供文档名、batchId、出现时间、页面显示的“原因/影响/下一步”和脱敏诊断包即可。不要发送 API Key、密码、Authorization 或服务连接信息。
